## 1 需求与验收

**要解决什么**：前两轮只测「测试是否通过」，测不出「逻辑是否更好」。用户要求验证质量维度。

**验收判据**：
- ≥5 模块、跨模块不变量的高难任务（事件溯源），25 条给定测试
- 隐藏探针 ≥10 条，严格由规格推出，且参考实现能全绿（证明公平）
- 盲评：代码拷到中性目录、随机打乱、冷上下文 reviewer 8 维打分、事后解盲
- 结论与证据写进 README 与 RESULTS.md
- `npm run verify` 绿

## 2 设计逻辑

三层测法，逐层提高区分度：

| 层 | 测什么 | 为什么能区分 |
|---|---|---|
| 给定测试（25） | 功能是否实现 | 两组都能过，不区分 |
| 隐藏探针（11） | 规格条款是否真的都实现 | 两组都没见过，只认「是否读懂规格」 |
| 盲评（8 维） | 结构、防御、可维护性 | 排除「谁写的」偏见，只看代码 |

探针公平性用参考实现校验：参考实现 11/11，才说明探针不是刁难。

盲评用一次性随机映射（写入只读 600 文件），reviewer 不知道 alpha/beta 对应哪组。
