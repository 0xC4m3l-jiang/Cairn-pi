## 1. 需求与验收

**要解决什么**：文档齐了但没有一行可运行实现，`pi -e` 指不到任何东西。

**做完之后，用户能做什么**：
- `pi -e <包目录>` 加载后用 `/cairn init|map|execute|integrate|status|report`
- 用节点图逐节点开发，依赖门/边界门/证据门/预算门在代码里强制
- `/cairn status` 看到覆盖矩阵，`/cairn report` 拿到追溯矩阵

**验收判据**：

1. `npm run verify` 通过（typecheck 覆盖 `lib/` 与 `extensions/`，测试全绿）
2. 端到端：init → map_write → 闸门 → claim → submit → verify → integrate → report 全链路可跑
3. 四道门禁各自拒绝非法操作：依赖未完成 / 改动越界 / 无证据完成 / 预算耗尽
4. `pi -e <包目录>` 能真实加载并执行 `/cairn` 命令
5. 用本包在样例仓库完成一次真实开发并让测试由红转绿

**不做什么**：并行节点执行、TUI 图形渲染、跨会话多项目、远程 server。

## 2. 设计逻辑

设计已定稿于 `DESIGN.md`（D1–D7）。本轮不改设计，只落地。落地时新增两个工具（`cairn_map_write`、`cairn_hint`），已同步 `DESIGN.md` §10.1。

**关键落地选择**：

| 选择 | 理由 |
|---|---|
| `cairn_node_verify` 支持 `run:true` 与提交证据两种模式 | 前者是权威路径（扩展自己跑命令），后者支持「独立 verify subagent」选择；两条路都过三层复核 |
| 闸门状态存在 `board.events` 的 `gate` 事件里 | 与审计流同源，不引入第二处状态 |
| `saveBoard` 用临时文件 + rename | 中断不会留下半个 JSON |
| `structure: lib/*` 不 import pi 运行时 | 90% 逻辑可脱离 pi 单测 |
