## 1 需求与验收

**要解决什么**：此前 A/B 只有单文件 todo（6 用例、~30 行），原生 pi 28s 做对，cairn-pi 的「多模块隔离 + 证据链」优势测不到。需要一个真正多模块、跨文件依赖的复杂任务。

**验收判据**：
- 复杂需求含 ≥4 模块、跨模块依赖、≥15 验收用例
- 参考实现 15/15 绿（证明测试正确），桩态 15/15 失败（正确起点）
- A/B 各跑一次，B 组 board.json 有 4 节点 done 且逐条证据
- README 与 RESULTS.md 回写复杂任务对比
- `npm run verify` 绿

## 2 设计逻辑

- 选「迷你图书借阅系统」：`books`/`members`/`loans`/`reports` 四模块；`loans` 依赖 `books+members`，`reports` 依赖三者——用工厂函数 + 依赖注入组合，正好体现 cairn 的「节点接口契约（provides/consumes）」。
- 测试隔离用工厂（每用例独立实例），避免单例状态跨用例污染。
- 配置适配：`node --test` 项目用 `.cairn/config.json` 写 `how: "node --test {tests}"`，避免简单任务里「`npm test -- {tests}` 多余参数」的偏差。
- 脚本沿用 `env -u PI_PACKAGE_DIR`（上一轮修复）。
