## 1 需求与验收

**要解决什么**：对比实验显示 B 组（cairn-pi）出现「约 240 秒空转」，且两项核心卖点被评「不太行」——追溯矩阵只输出节点标题、不含需求原文；中断后 running 节点卡死无恢复路径。

**验收判据**：
- 技能含硬性停止判据；扩展在「全部节点完成」时显式提示收尾（代码可核）
- `cairn_node_claim` 一次返回节点完整切片（省一次 `cairn_board_read` 往返）
- `cairn_report` 输出「需求」与「验收判据」两列
- 新增 `/cairn resume`，把 running 节点重置为 ready
- `npm run verify` 绿

**不做什么**：不改配置阶梯默认值（unit/acceptance 重复是用户配置问题，非本轮范围）、不重跑 A/B 实验复现耗时、不动 demo 脚本。

## 2 设计逻辑

- **空转根因**：技能只有「进入 integrate」的软提示，没有「完成后停止」的硬判据；agent 在最后一步无指令可依，空转等待。
- **修复**：`cairn_node_verify` 在节点 done 且全节点 done 时返回「立即 integrate → report → 停止」；`cairn_integrate` 在目标达成时返回「输出 report 后立即停止」；两个技能加「硬性停止」段。
- **追溯做实**：`TraceRow` 增加 `requirement`、`acceptance` 两字段，`renderReport` 表头加两列。
- **恢复做实**：新增 `/cairn resume` 子命令，扫描 running 节点重置为 ready，并记录 `replan(phase=resume)` 事件。
