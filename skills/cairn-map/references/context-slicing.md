# 上下文切片规则

每个节点的 subagent 只拿「需求 + 接口 + 约定」。多给任何一样都是噪声。

## 节点 subagent 的 prompt 模板

```text
你在实现一个节点。不要看其它节点的实现，也不要猜整体计划。

## 节点
<node.id> — <node.title>
模块：<node.module>（<模块一行定位>）

## 需求（只属这个节点）
<node.requirement>

## 验收判据
<node.acceptance 逐条>

## 必须产出的测试
<node.tests>

## 可以改的文件（越界会被拒绝）
<node.touches>

## 上游给你的接口（只看签名，别去读实现）
<每个 dep 的 provides>

## 项目约定
<AGENTS.md 摘要 / 风格 / 构建与测试命令>

## 完成标准
1. 节点需求全部实现
2. acceptance 每条都有对应测试
3. 只改允许的文件
4. 停下时用一句话陈述产出，然后调用 cairn_node_submit
```

## 明确**不给**的东西

| 不给 | 原因 |
|---|---|
| 整体计划全文 | 会让子代理按「看起来合理」写，而不是按需求写 |
| 其它节点的对话历史 | 上下文污染，且会诱导模仿 |
| 依赖节点的实现细节 | 只该依赖签名；读了实现就会跟着抄错 |
| 失败节点的完整排错过程 | 只给失败级别 + 摘录，否则会在错误假设上继续推 |
| 全局架构图全文 | 一行模块定位足够 |

## 验证者 subagent 的 prompt 模板

```text
你是独立验收者。不要读实现思路，也不要修改任何文件。

## 被验证的主张
<claim>

## 验收判据
<acceptance>

## 要跑的检查（原样执行，不要替换成别的命令）
<逐级的 how 渲染结果>

## 输出
1. 每级：命令原文 + 退出码 + 输出片段
2. 判定：pass 还是 fail
3. 失败时指出是哪一级、哪条判据
```

验证者的工具集**不含 write/edit**。若能顺手修掉问题，验证就退化成自证。

## 组 Agent 的输入

| 给 | 不给 |
|---|---|
| 各节点产出摘要 | 节点内部推理 |
| 各节点 diff | 完整对话 |
| 接口契约表（provides/consumes 汇总） | 中间试错过程 |
| 整体验收命令 | —— |
