# cairn-integrate：拼接与整体验收

## 输入受限

组 Agent **只拿**这些：

| 给 | 不给 |
|---|---|
| 各节点产出摘要（claim + changedFiles） | 节点内部推理过程 |
| 各节点 diff | 完整对话历史 |
| 接口契约表（`provides` / `consumes` 汇总） | 中间试错记录 |
| 整体验收命令 | —— |

给了推理过程，组 Agent 的上下文会被 N 个节点撑爆，直接退化成单发 agent——那正是这套设计要避免的。

## 步骤

1. `cairn_report` 取追溯矩阵，确认所有节点 `done` 且 `probe` 级都有证据（规格探针不是可选）
2. 按依赖顺序检查各节点 `provides` 是否与下游 `consumes` 对得上
3. 处理接缝：签名不一致、类型不匹配、遗漏的边界调用
4. `cairn_integrate` 跑模块级整体验收
5. `cairn_coverage` 确认目标达成

## 冲突处理

| 冲突 | 处理 |
|---|---|
| 两个节点改了同一文件 | 这是地图缺陷（`touches` 重叠），记录并回报，不要硬合 |
| 上游签名与下游期望不符 | 以 `provides` 声明为准；若实现偏离声明，回该节点重做 |
| 集成测试暴露跨模块逻辑错 | 用 `cairn_hint` 记录，并指出该回哪个节点 |

**不要**在 integrate 阶段偷偷改节点内部实现来让测试变绿——那会绕过证据门。
需要改代码时，回到对应节点重新走 claim → submit → verify。

## 完成判据

`cairn_coverage` 报告：

```text
目标 T0  ✓ met
```

即：全部节点 `done`，且 `integrate` 范围的每个必需级别 `exit 0`。

**硬性停止**：`cairn_integrate` 返回「目标已达成」后，输出 `cairn_report` 追溯矩阵，然后**立即停止**——不要再调用任何工具、不要等待、不要重复检查。

## 收尾输出

1. `cairn_report` 的追溯矩阵（节点 ↔ 验收级别 ↔ 证据）
2. **未验证项**：显式列出，不要让人以为都验过
3. 遗留与风险：模块级测试没覆盖到的路径、已知绕行

未达成目标时，明确写出卡在哪：哪个节点 failed、失败的是哪一级、下一步是重试还是重规划。
